### Recap of Part 3: concept learning and Find-S
- Concept learning: learn a yes or no function from labelled examples
- Hypothesis: six constraints, each a value, ? or ∅
- Find-S: start at all ∅, generalise on positive examples only
- Its weakness: one answer, negatives ignored, no way to know about other fits

### Consistent hypotheses
- h is consistent with the data if h classifies every training example correctly
- Positive examples must be covered, negative examples must be rejected
- <Sunny, ?, ?, ?, ?, ?> is consistent with all four EnjoySport examples
- <?, ?, ?, ?, ?, Same> is not: it rejects positive example 4

### The version space
- Version space: the set of all hypotheses consistent with the training examples
- Find-S gave one member; the version space holds all of them
- A version space shrinks as more examples arrive
- If it ever becomes empty, no hypothesis in our space fits the data

### List-Then-Eliminate: the brute force way
- 1. Version space = a list of every hypothesis
- 2. For each training example, delete every hypothesis that classifies it wrongly
- 3. Output what remains
- Correct, but impractical when the hypothesis space is large

### The two boundaries: S and G
- S, the specific boundary: the most specific consistent hypotheses
- G, the general boundary: the most general consistent hypotheses
- Every consistent hypothesis lies between S and G in the general-to-specific order
- So two small sets describe the whole version space

### The candidate elimination algorithm
- Start: G = {<?, ?, ?, ?, ?, ?>}, S = {<∅, ∅, ∅, ∅, ∅, ∅>}
- Positive example: drop members of G that reject it; generalise S minimally to cover it
- Negative example: drop members of S that cover it; specialise G minimally to reject it
- Keep only hypotheses that stay between S and G

### Minimal specialisation in code
- Change one ? into a value that differs from the negative example
- Keep it only if it is still above some member of S

```python
def specialise(g, x, S, DOM):
    # g covers a negative example x; make it reject x
    out = []
    for i in range(6):
        if g[i] == "?":
            for v in DOM[i]:
                if v != x[i]:
                    h = g[:i] + (v,) + g[i+1:]
                    if any(more_general(h, s) for s in S):
                        out.append(h)
    return out
```

### The final version space
- S4 and the two members of G4 are the boundaries
- Three more hypotheses lie in between
- Six consistent hypotheses in all

### The boundaries squeeze together
- S covers more days as it generalises
- G covers fewer days as it specialises
- When S and G are the same single hypothesis, the concept is learned

### Using the version space to classify new days
- All hypotheses say Yes: classify positive
- All say No: classify negative
- A split vote: the learner is not sure yet

### Inductive bias
- We assumed the target is a conjunction of attribute constraints
- This assumption is the inductive bias of the algorithm
- A learner with no bias can only repeat the examples it has seen
- Correct answers need: target inside the space, and no noisy examples

### Common mistakes to avoid
- Starting S and G the wrong way round
- Forgetting to remove G members that reject a positive example
- Specialising G without the check that it stays above S
- Letting a negative example change S, or a positive one change G beyond removing members
